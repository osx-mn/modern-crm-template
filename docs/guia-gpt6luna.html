02 / APLICACIÓN WEB

Next.js — lo que ve la persona

Framework construido sobre React. Aquí usa App Router, TypeScript y la carpeta src/.

apps/webABRE UNA FILA PARA PROFUNDIZAR
▾src/app/Rutas y UI de la aplicaciónCon App Router, los archivos especiales dentro de app definen páginas y layouts. La estructura de carpetas organiza segmentos de URL.
◧page.tsxPágina de la ruta raíz /Es el punto de entrada visual para la ruta principal. Un archivo page.tsx vuelve accesible una ruta de App Router.
▤layout.tsxMarco compartido entre páginasEl layout raíz envuelve las páginas; suele definir HTML, body, metadatos y elementos persistentes de navegación.
◌globals.cssEstilos globalesReglas CSS compartidas por toda la app, importadas desde el layout raíz.
⚙next.config.tsConfiguración de Next.jsOpciones del framework. Vive en la raíz de apps/web; no es una página ni define una ruta.
⌘package.jsonDependencias y scriptsnpm run dev ejecuta next dev, npm run build prepara producción, y npm run start sirve la build.
▧public/Archivos estáticosRecursos servidos directamente, como el favicon actual. No es donde se definen páginas.
MODELO MENTAL

Carpeta = ruta.
Archivo = convención.

Next reconoce nombres como page.tsx y layout.tsx. No son nombres elegidos al azar: activan comportamientos del router.

03 / SERVIDOR DE APLICACIÓN

NestJS — donde viven las reglas

Un framework de Node.js que ordena el backend en piezas con responsabilidades claras.

La arquitectura Nest

apps/api/src

Piensa en una petición que atraviesa tres roles:

  • main.tsArranca la app; aquí se configuran validación global, CORS, cookies y el puerto.
  • app.module.tsConecta módulos, controladores y proveedores; es el módulo raíz.
  • *.controller.tsRecibe y enruta solicitudes HTTP; expone endpoints.
  • *.service.tsImplementa operaciones y lógica de aplicación.
  • *.spec.tsPruebas unitarias asociadas al código fuente.

Las tres piezas

SOLICITUD ↓
  • ModuleOrganiza una capacidad y declara sus dependencias.
  • ControllerTraduce HTTP a una llamada de aplicación.
  • ProviderObjeto inyectable: service, repositorio u otra ayuda.
↳

En este repo, AppModule importa PrismaModule. Ese módulo ofrece PrismaService, que comparte el cliente de base de datos.

04 / MODELO DE DATOS

Prisma — del esquema a la consulta

Describe el dominio una vez, aplica cambios con migraciones y genera un cliente para TypeScript.

La ruta de los datos

DISEÑO → POSTGRES
  • schema.prismaDefine User, Customer, Deal, Note y enum DealStage.
  • migration.sqlHistorial versionado de cambios aplicados a la base.
  • prisma7.config.tsConfigura schema, carpeta de migraciones y DATABASE_URL.
  • src/generated/prisma/Cliente y tipos generados; no editar a mano.
  • PrismaServiceExtiende PrismaClient y conecta usando el adaptador PostgreSQL.

Relaciones que cuentan la historia

CRM
  • User 1 → NUn usuario puede ser propietario de varios clientes.
  • Customer 1 → NUn cliente puede tener varias oportunidades y notas.
  • DealStageLEAD → CONTACTED → PROPOSAL → WON / LOST.
  • DATABASE_URLCadena de conexión; vive en entorno/configuración, no hardcodeada en el schema.
i

En Prisma 7 de este proyecto, el schema declara el proveedor PostgreSQL, y la URL está en prisma7.config.ts. El adaptador @prisma/adapter-pg crea la conexión desde la API.

05 / FLUJO DE TRABAJO

justfile — botones para el equipo

Un archivo de recetas shell-agnósticas: cada nombre es un atajo reproducible desde la raíz.

Recetas que ya existen

just <receta>
justLista las recetas disponibles.
just dbLevanta PostgreSQL con Docker.
just db-downDetiene los servicios del compose.
just apiAPI en watch, desde apps/api.
just webNext en desarrollo, puerto 3000.
just migrateEjecuta Prisma migrate dev.
just generateGenera el cliente Prisma.
just studioAbre Prisma Studio, puerto 5555.
just installInstala API y frontend.
!

El orden típico para trabajar: just db → configurar variables de entorno → just migrate y just generate → just api + just web. Son procesos separados: deja ambos servidores corriendo.
